Key Decisions
EntityManager with native SQL for all admin aggregation queries (existing JPA repos join too many tables).
BINARY(16) UUID conversion handled in service layer with byte array parsing.
Admin delete sets activity_status = DELETED (not INACTIVE). Admin deactivation = INACTIVE.
Catalog delete safety checks at DB level: category inUse = EXISTS in skill table; skill inUse = EXISTS in freelancer_skills OR posting_skills.
Posting detail skills/attachments fetched via GROUP_CONCAT with '||' separator to avoid N+1 queries.
Posting listing includes ALL activity_statuses (no filter) so deleted postings appear in the table.
"/office/" endpoints all require ADMIN role (SecurityConfig + @PreAuthorize).
Flag list target display resolved via 3-way LEFT JOIN (users for profiles, postings for postings, reviews→users for reviews) in a single query.
FlagReportDialog created as standalone component (not modifying generic ConfirmDialog) to keep concerns separate.
Flag reporting moved from parent callback pattern (onReport) to self-contained dialog that calls API directly.

Critical Context
MySQL sql_mode=only_full_group_by requires all SELECT columns to be in GROUP BY or aggregated; fixed all GROUP BY queries with subquery wrapping.
Hibernate returns LocalDateTime for DATETIME columns and java.sql.Date for DATE columns (not java.util.Date).
Existing reusable services: PasswordResetService.sendResetEmail(email), VerificationService.sendVerificationEmail(username), UserSecurityService.deleteAccount(userId).

Posting entity: budget (Integer), status (PostingStatus: ACTIVE/CLOSED), experienceLevel (ExperienceLevel: ENTRY/MID/SENIOR/EXPERT), activityStatus (BaseEntity), categoryId (UUID, not JPA relationship), location (ManyToOne to Location), client (ManyToOne to Client).
Skill entity: skill field maps to column skill (name), category → category_id FK.
Posting_skills: skill_id FK, posting_attachments: ElementCollection table.

FlagType enums stored with @Enumerated(EnumType.STRING) — SQL comparisons use enum name (e.g., 'FLAG_PROFILE', not 'flag_profile').
